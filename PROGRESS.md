**Step 6 of the agent build: orchestrator, case file, Markovian rounds (Phase 7 step 1, Phase 8 steps 2 and 3).** `src/agent/orchestrators/investigate.ts`: once the contract checks out, the orchestrator splits the change, opens the case file and runs Markovian steps. Each step, Ultra reads the case file and the carried-over state and either hands out tasks or closes the case; code runs the specialists it asked for in parallel and writes their findings back. Step 1 sends every specialist; at most two follow-up rounds, one follow-up per specialist; code decides if Ultra's reply is unusable twice. `src/memory/casefile.ts` keeps the case in World Model: bills and causes as entities, the split, findings, follow-ups and reviews as facts with provenance; a later finding supersedes the earlier one and both stay in the history and audit. `runOrchestrator` runs the investigation when given a data source (the page still gets the placeholder until Phase 9). Engines import as `#meterless/*` (package.json `imports`); Node scripts that load them need `--experimental-transform-types`.
Live trial (`npm run try:orchestrator`) on gas-january, elec-april, water-summer-leak and control: answer key 24 of 24; Ultra planned, reviewed once and closed each case; 19 to 25 model calls (2 Ultra), every call with a Nightshift receipt; 24 to 57 s a utility. 118 tests pass, lint clean, `next build` passes.
Found: World Model closes an open edge when the same source gets a new edge of the same type, so causes link to the case (`cause -tested_in-> case`), not the other way. Ultra's first run spent both follow-ups re-asking usage about a £1.79 part already ruled out; the case file now counts a part as accounted for when all its causes were checked and ruled out, shows the follow-ups already asked, and each specialist gets one follow-up. Time per question is mostly rate pacing (LLM_RPM 30: 19 calls need about 38 s); a higher NVIDIA limit would cut it.

**Step 8 of the agent build: household memory in H-MEM (Phase 8 steps 1 and 4).** `src/memory/hmem.ts`: notes (M1, M2, … in creation order, with the date they talk about), recall through H-MEM's hybrid retrieval, findings saved from each checked answer with their evidence ids, thumbs feedback on the notes and findings behind an answer, and H-MEM's trust ledger as the audit. Persisted under `HMEM_PATH` (`.memory/`, gitignored). `recall_notes` returns the notes that could bear on the bills, ranked, and `test_cause` accepts only note ids the agent actually recalled. Part figures carry the note ids behind them, so the text cites `[M1]`.
Live (`npm run try:orchestrator -- "--note=We installed a heat pump on 15 March 2026" elec-april`): the usage agent recalled the note and passed M1 to the fuel-switch test; the checked answer cites [M1] (without the note it doesn't); ledger: 5 created (the note and 4 findings), 1 read. 133 tests pass.
